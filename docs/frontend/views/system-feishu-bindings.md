# 飞书绑定（FeishuBindings.vue）

**路由：** `/system/feishu-bindings`（`perm: ['account', 'write']`）
**文件：** `src/views/system/FeishuBindings.vue`
**后端：** [飞书接入模块](../../backend/modules/im_mgr.md)

---

## 职责

维护「哪个飞书账号能以哪个平台账号登录与发起执行」。用飞书登录一次会按企业邮箱
自动绑定，匹配不上时在这里手工绑。

菜单位置：系统管理 → 飞书绑定。权限挂 `account` 而不是 `system`——绑定关系属身份面，
和用户、角色、API 凭证同一个风险面。

---

## 页面结构

```
飞书绑定
├── toolbar：关键字搜索（平台用户 / 飞书昵称 / 邮箱）+ 手工绑定
├── el-table：平台用户 / 平台邮箱 / 飞书昵称 / 飞书邮箱 / 绑定来源 / 最近飞书登录 / 解绑
└── el-pagination
```

只有「查 / 新增 / 解绑」三件事，**没有编辑**：改绑等于解绑再绑，两步各自留痕，
后端也没开更新接口。

---

## 手工绑定弹窗

管理员手上通常只有邮箱或手机号，所以流程是「先查人、再选账号」：

1. 一个输入框同时收邮箱与手机号——带 `@` 当邮箱，否则按手机号，不让管理员先选类型；
2. 查到后展示飞书昵称与 UnionID，让人确认绑的是同一个人；
3. 平台账号用远程搜索下拉（`getUsers`，按用户名过滤）；
4. 未查到成员或未选账号时「绑定」按钮保持禁用。

---

## 解绑确认

文案写明两层后果：解绑后该用户无法用飞书登录、发起执行或处理暂停；**若该账号没有
可用密码（飞书自动创建的），解绑后将再也无法登录**。第二条是真会把人锁在门外的那条。
