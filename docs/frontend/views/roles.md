# 角色权限（`/system/roles`）

**组件：** `src/views/system/Roles.vue`
**API：** `src/api/users.js`（`getRoles` / `getRoleMeta` / `createRole` / …）
**权限：** `account` 模块 write 档；写操作后端要求 sudo，由 `utils/request` 拦截器统一处理。

角色 = 模块权限矩阵 + 执行能力位。后端语义见
`docs/backend/modules/auth.md` 的「角色与权限矩阵」。

---

## 页面结构

- 表格：角色名（内置标记）、标识、**模块权限概要**（按分组一个标签，形如「任务执行 3/5」，
  悬停弹出该组逐模块档位）、执行能力、用户数、状态
- 弹窗：基本信息 → 按分组分块的模块权限（每模块一组单选按钮，组标题带「全部无权限 /
  全部只读」快捷键）→ 执行能力 → 启用

模块拆到 13 个之后，「每个模块一列」的表格已经排不下（也没人横着读得完 13 列），
所以列表页给分组概要、详情放进弹窗与悬停浮层。

模块清单、**分组**与**每个模块的可选档位**都由后端 `roles/meta/` 提供，前端不硬编码
——加一个模块时不用同步改两边，也不会出现「前端少列一个模块，管理员以为没配过」；
可选档由后端给还保证了页面上不会出现「点了不生效」的档（如操作审计的读写档）。

---

## 交互要点

| 点 | 行为 |
|----|------|
| 权限档色阶 | 读写 success / 可读可新增 warning / 只读 info / 无权限 danger |
| 标签短名 | 模块说明形如「服务器资产（服务器台账…）」，标签只取括号前的短名 |
| 分组概要色阶 | 全组已授权 success / 部分授权 warning / 全组无权限 info |
| 档位收窄 | 只渲染该模块的可选档，并在说明后标「· 仅这几档有效」 |
| 分组快捷键 | 「全部无权限 / 全部只读」按该模块的可选档退档，不会写入配不出来的值 |
| 含生产 | 「可执行」关闭时置灰；提交前强制 `can_exec_prod = can_execute && can_exec_prod`，不留「看着开着实则不生效」的开关 |
| 内置角色 | 不显示删除按钮（后端也会拒）；`super` 降档由后端拦下并给出明确报错 |
| 删除 | 二次确认文案说明「仍有用户在用会被拒，请先改这些用户的角色」 |
| 保存提示 | 「已保存（绑定该角色的用户立即生效）」——矩阵是实时判定的，不需要重新登录 |

## 用户页联动（`/system/users`）

- 列表「角色」列显示真实角色名；未配角色时显示「管理员（未配角色）」/「普通用户（未配角色）」，
  提示这些账号走的是 `is_staff` 回退
- 表单新增「角色」下拉与「数据范围」（项目组 / 环境多选，留空 = 不限）
- 「管理员」开关保留：它是 Django 后台入口，也是未配角色时的权限回退依据

## 菜单与按钮可见性

`Layout.vue` 的侧边栏按模块权限渲染（`authStore.can(module, action)`）：子项逐个判，
**整组都看不到时连父菜单一起藏**——留一个点进去全是 403 的空目录没有意义。

页面内的按钮判定也已从 `isStaff` 迁到矩阵（视图里已无 `isStaff` 引用）：

| 页面 | 判定 |
|------|------|
| 服务器 / 服务器分配 | 新增按 `can('cmdb', 'create')`、改删按 `can('cmdb', 'write')`；「执行通道」两个字段另看 `can('agent')`（选项来自 Agent 接口）|
| 字典管理 | 新增按 `can('dict', 'create')`、改删按 `can('dict', 'write')` |
| 域名 / 证书 | `can('cloud', 'write')`；「变更审批」是批/驳入口，同样按写档判（「变更留痕」是只读，保留）；账号下拉看 `can('cloud_account')` |
| 云账号 | `can('cloud_account', 'write')`（只读档能看清单，AccessKey 由后端打码）|
| 任务列表 / 执行日志 | 改定义 `can('exec', 'write')`；发起执行与处理暂停看能力位 `capability('can_execute')` |
| 变量 / 制品 | `can('variable', 'write')` / `can('artifact', 'write')` |
| 日志文件 / 执行现场 | `can('exec')` 只读档即可 —— 与执行日志详情同一份内容 |

**新增按钮必须按 `create` 档判，不能跟改删共用一个 `canWrite`**：`cmdb` / `dict`
有「可读可新增」这一档，只读档的人看到新增按钮点下去就是 403；反过来把新增并进
写档，又会让「可读可新增」这一档在页面上根本用不出来。

依赖多个模块的下拉（证书页要账号 + 主机 + 凭据）**逐个按各自模块取**：
`Promise.all` 一拒全拒，缺一个模块的权限不该把整页选项都带走。

前端判定始终只是「少让人点到必然 403 的按钮」，真正的判定在后端。
