# 拓扑画布（views/topo/Canvases.vue · CanvasEditor.vue）

**路由：** `/topo/canvases`（列表）· `/topo/canvases/:id`（编辑器，URL 可分享）
**菜单：** 侧边栏「资产管理 → 拓扑画布」，与服务器台账同组
**权限：** `meta.perm = ['topo', 'read']`；写操作按 `authStore.can('topo', 'write')` 显隐
**API：** `src/api/topo.js`（`/api/topo/`，后端模块见 `docs/backend/modules/topo.md`）
**依赖：** `@vue-flow/core`（画布）· `@vue-flow/background` · `@vue-flow/controls` · `dagre`（自动排版）
**通用组件：** `components/ContextMenu.vue`（右键菜单）· `components/TopoImpactDialog.vue`（影响面反查）

---

## 列表页（Canvases.vue）

- 筛选：关键字（名称/标识，300ms 防抖边输边查）+ 项目组 / 渠道 / 环境下拉（字典启用项）。
- 列表：名称（可点开画布）/ 标识 / 维度 tags（生产环境 danger 红标）/ 规模（节点数 + 连线数）/
  说明 / 创建人 / 更新时间。地域留空显示「跨地域」并置灰。
- 新建：名称 + 标识 + 项目组 / 渠道 / 环境 / 地域 + 说明。
- 编辑**只允许改名称与说明**：维度与标识是画布的身份，改了等于换成另一张图，而图上
  节点是按原维度挑出来的，跟着换会得到一张自相矛盾的图。表单里这些字段直接 disabled。
- 删除：二次确认，文案报出会一并删掉的节点/连线数量，并明确**被引用的服务器、域名与
  证书本身不受影响**——这是运维最担心的一件事，不写清楚没人敢点。

## 编辑器（CanvasEditor.vue）

三栏布局，与参考实现同构：

| 区域 | 内容 |
|------|------|
| 顶部 | 返回 / 画布名 + 维度 tags / 未保存标记；右侧：值班开关 · 撤销 · 重做 · 重新加载 · 自动编排 · 重新排版 · 更多（导出/克隆）· 保存 |
| 左侧调色板 | 「平台资源」四类（点击开候选弹窗）+ 外部节点按云厂商分组（点击加入画布） |
| 中间画布 | VueFlow：拖拽移动、拖连接桩连线、滚轮缩放、右下角控制条、点网格背景 |
| 右侧详情 | 选中节点/连线的属性编辑与删除；未选中时显示画布概况与失联节点数 |

### 撤销 / 重做

**快照式**，不是命令式：图上就几十个节点，整份深拷贝的代价可以忽略；命令式要为每种
操作写一对 do/undo，删节点还得记住它身上的连线——写十种就有十种写错的机会。

- 栈上限 50 步。栈底是「刚从服务端加载/保存完」的那一份，所以**撤销栈空 = 回到了那个
  状态**，`dirty` 直接跟着栈深走，不用另猜「现在到底改没改」。
- 入栈时机一律在**改动之前**（存的是「改之前长什么样」）。三处特殊：
  - 拖拽在 `node-drag-start` 抓快照，`drag-stop` 比较坐标，**真挪动过才入栈**——
    单击节点也会走一遍 drag-start/stop，不比较的话点一下就多一条历史，还会误标未保存；
  - 右侧面板的文本框在 `focus` 时只**暂存**快照，敲了第一个字才入栈，一次聚焦只记一步
    （否则每敲一个字入一次栈，撤销要按几十下）；
  - `v-model` 已经改掉值的控件（固定位置开关、关系下拉），快照按旧值重建再入栈；
    关系下拉的旧值在 `@focus` 时记下（`el-select` 的 `@change` 只给新值）。
- 删除节点的入栈放在**确认框之后**：取消掉的确认不该留下一条历史。
- 撤销/重做刻意**不重置视口**：人正盯着某一块看，视图跳一下比不跳更难受。恢复时会先收
  掉改名态与右键菜单——节点对象整份换掉，指向旧对象的状态全部作废。
- 保存或重新加载后清栈：服务端刚给的那一份是新基线，撤到那里就到底了。
- 入口三处：工具栏按钮（带禁用态与快捷键提示）、`Ctrl/Cmd+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`、
  空白处右键菜单。输入框内的 `Ctrl+Z` 不拦——那是浏览器的文本撤销，抢过来会让人改不了字。

### 右键菜单与就地改名

高频操作（改名 / 删除 / 改关系 / 固定）原来全在右侧面板：要先点中目标，再把视线和
鼠标挪到屏幕另一边。现在同时挂到右键上，右侧面板保留不动——问题清单、实时附加信息、
备注、副标题只有那儿放得下。

| 触发 | 菜单项 |
|------|--------|
| 节点上右键 | 重命名（引用型置灰并说明「取自平台资源」）· 固定/取消固定 · 打开原始页（引用型）· 查看所在其它画布 · 复制名称 · 断开所有连线（带条数，无连线置灰）· 删除节点 |
| 连线上右键 | 改关系（7 种平铺，当前值打勾）· 删除连线 |
| 空白处右键 | 在此处新建节点（按云厂商二级菜单）· 重新排版 · 适应视图 |

- **就地改名**：双击节点标题或菜单里的「重命名」，原地变输入框，Enter 提交 / Esc 取消 /
  失焦提交。新建外部节点后自动进入改名态——加一个节点后要做的事十有八九是给它起名。
  引用型节点双击标题改为打开原始页：它的名字本来就该在那边改。
- **类型标签也能改**：节点卡片上那行蓝字（「AWS · GA 加速器」）双击即可编辑，引用型节点
  同样可改——它只是给人看的分组名，真实类型始终是 `data.kind`，改它不影响任何判定。
  值存在 `attrs.kind_label`（后端零改动：`attrs` 就是为这类展示细节留的自由字段），
  清空即恢复 `/api/topo/meta/` 给的默认名。右侧面板的「类型标签」一栏与右键菜单的
  「修改 / 恢复默认类型标签」走同一条路；面板那栏用 `@change`（失焦/回车）而不是
  `@input`，否则每敲一个字入一次历史栈。
- **落点**：空白处右键新建的节点落在**光标处**（`screenToFlowCoordinate` 换算画布坐标），
  不再是按节点数错开的固定位置；从左侧调色板加则仍走错开落点。
- **键盘**：Delete / Backspace 删选中的节点或连线；`Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做。自己接而不是交给 vue-flow 的
  `deleteKeyCode`——那条路不走确认框、也不会把改动标成未保存；输入框内的退格照常编辑文字。
- **确认口径**：带连线的节点才二次确认（删掉会静默改变链路形状，那种错不容易发现）；
  孤立节点直接删——删错了 `Ctrl+Z` 撤回。
- **只读 / 值班模式**：菜单只留「看」的动作（打开原始页 / 查看所在画布 / 复制名称），
  键盘删除与撤销重做都不生效。给一堆点了没反应的菜单项比不给更糟。

四个实现上必须处理的点，都在代码注释里写了原因：节点内输入框要 `@mousedown.stop`
（否则一点就开始拖节点）；菜单用 `Teleport` + fixed 定位（挂画布内部会被 transform
缩放）；整图刷新与菜单动作前先收掉改名态（节点对象会被换掉）；值班模式定时刷新在
改名中跳过那一轮（与未保存改动同口径）。

vue-flow 默认只有左键平移（d3-zoom 的 `!event.button` 过滤），所以右键菜单不会和画布
拖动抢事件，不需要关掉 `panOnDrag`。

### 节点 id 用客户端 key，不用数据库主键

新拖出来的节点还没有主键，而连线必须立刻能引用它。所以画布内的 id 一律是客户端
key（已落库的用 `n<主键>`，新建的用 `new-<序号>`），主键另存在 `data.dbId` 里，保存
时回传以更新而非重建。后端整图 PUT 按 key 关联连线（见 `apps/topo_mgr/graph.py`）。

### 调色板分两类

- **平台资源**（服务器 / 主域名 / 解析记录 / 证书）：点击开候选弹窗，从后端
  `candidates` 拉清单（主机按画布维度收窄）。已在图上的资源仍然列出并标「已在图上」，
  不是过滤掉——过滤掉的话用户会以为是搜不到。
- **外部资源**（GA、各家 LB、CDN、WAF…）：点击直接落一个可改名的节点。分组结构来自
  后端 `/api/topo/meta/`，前端不写死一份：加一种负载均衡只改后端登记表，否则漏改的
  表现是「拖得出来但存不进去」。

### 引用型节点的名称不可改

它的名称、副标题、状态由平台实体决定，右侧详情只展示不给编辑（改了保存后仍会被实时
值覆盖，给一个改不动的输入框比不给更糟）。节点卡片左侧色条是健康度，颜色口径与列表页
`el-tag` 一致：绿=正常、黄=警告、红=异常或**已失联**。

失联节点（引用的实体被删）留在图上并弹红色 alert 提示，不静默消失。

### 保存与自动编排

- **保存**：整图一次 PUT，后端事务覆盖。保存后用响应里回传的整图刷新画布——新节点在
  这里第一次拿到主键，引用型节点也拿到实时状态。坐标从 VueFlow store（`getNodes`）读，
  不依赖 v-model 回写的时机。
- **自动编排**：有未保存改动时先拦住（提示先保存），否则新拉的节点会和本地改动混在
  一起，保存时谁覆盖谁说不清。确认框里写明会拉哪些资源、幂等、不动手摆好的节点。
- **重新排版**：dagre `rankdir=LR` 从左到右分层。`data.pinned` 的节点不动——人手摆的
  位置通常带着说不出口的信息（这条链路要横着看），被一次排版抹掉很恼人。
- 有未保存改动时，「重新加载」二次确认、浏览器刷新/关闭走 `beforeunload` 拦截。

### 导出 / 克隆（编辑器「更多」下拉）

- **导出 JSON**：后端吐的是 JSON 对象（引用型节点用自然键），前端落成
  `topo-<slug>.json`。不用 blob 响应类型，是为了让统一响应拦截器照常处理错误——
  blob 模式下后端的中文报错会变成一坨二进制。
- **克隆**：填新名称/标识，维度留空即沿用原画布。换了维度时与新维度不符的主机会被
  后端跳过，前端把跳过清单逐条弹出来（只报个数量，人不知道要补哪些）。克隆后 push
  到新画布——同一个组件实例，所以 `watch(canvasId)` 负责重新拉图，否则标题换了图没换。

### 导入（列表页「导入 JSON」）

选 `.json` 文件（`FileReader` 读成文本，不走 multipart——后端收的是 JSON 体）或直接
粘贴。可覆盖名称/标识/维度；「覆盖已存在」需读写权限，关闭时同维度同标识会直接报冲突。
落地结果同样弹出跳过清单。

### 影响面反查（components/TopoImpactDialog.vue）

通用弹窗，服务器页与域名页的行操作各挂一个「拓扑」按钮（按 `authStore.can('topo')`
显隐——没有画布权限的人看到一个点开就 403 的按钮只会困惑）。

弹窗左右两栏：上游（谁的流量落到它身上）/ 下游（它指向谁），每条带关系标签与邻居
节点名，节点名按健康度着色（口径与画布节点一致）。点画布名跳进那张图。

做成组件而不是各页面各写一份：两个页面问的是同一个问题，两份实现迟早在「上游/下游谁
是谁」上说反。

### 值班模式（P3）

顶部开关，状态同步到 URL（`?watch=1`）——大屏那份链接可以直接分享，刷新浏览器也还在
值班模式。开着时：

- **只读**：`editable = canWrite && !watchMode`，连有写权限的人也锁住——一张定时自动
  刷新的图上做编辑，下一次刷新就把改动冲了；
- 每 30 秒重拉整图（有未保存改动时跳过这一轮，绝不冲掉正在画的东西）；30 秒是「大屏
  挂着看」的量级，主机状态与证书天数都不是秒级变化的东西；
- 顶部横幅按最坏级别着色，给出「N 个节点异常 / 全部正常」+ 最近刷新时刻 + 立即刷新；
  横幅数字直接由画布上的节点算（`issueSummary`），不额外拉健康度接口；
- 异常节点呼吸高亮（`.pulse`）：大屏离得远，只靠 4px 色条看不见。

从编辑态切进值班模式时若有未保存改动，先二次确认再丢弃。

### 主机节点上的服务标签

主机卡片下方一行标签，注明这台机负责跑哪些服务（数据见
`docs/backend/modules/topo.md` 的「服务标签」一节）：

- 标签文字是**进程名 ×进程数**（`nginx-01×4`），与「服务器分配」页的「服务进程
  （规划/部署）」列同口径。进程名才是这台机上实际跑的那个东西的标识（同云厂商+项目组+
  环境+渠道内按服务类型自动递增编号），排查时要 grep 的就是它；服务类型名（「战斗服」）
  是分类，同一类在不同机器上重名，写在卡片上等于没说这台机跑的是哪一个。没规划过进程名
  的旧记录回落到类型名。类型名放 hover 与右侧面板——卡片要短，但「nginx-01 是干什么的」
  也得能问出来。
- `deployed` 实心绿、`planned` 虚线黄——一眼分清「在跑」和「还没上」。
- 卡片最多铺 **3 个**，多的收成 `+n`，hover 显示全部（带状态与进程名）。一台机六个
  服务全铺开，卡片会比别的节点高一倍，整张图的行距就乱了。
- 顶部「服务」开关控制显隐，存 `localStorage`（键 `topo.showServices`，默认开）——
  与概览页区块显隐同口径，按人记不进后端：它不影响任何人看到的数据，只影响这台
  浏览器上卡片有多高。读写都包了 try，隐私模式下取不到就用默认值。
- **dagre 布点高度跟着它走**（`nodeHeight()`）：卡片高了还按固定 78 布点，「重新排版」
  一按就叠在一起。
- 右侧面板另有「服务进程」一栏：进程名 tag + 进程数 + 服务类型名 + 状态。通用的
  `extra` 键值行显示不了这些，所以 `services` 从那份通用渲染里摘出来单列。

### 节点问题清单

右侧详情的「问题」一栏列出后端给的 `issues`（黄/红分色）：主机维护中、执行通道 Agent
离线、解析记录已停用、证书还剩几天……只给颜色不给原因，人还得自己去翻三个页面。

### 列表页的「健康」列

列表拉完后再补一发 `/api/topo/health/`（汇总要遍历所有引用型节点，绑进列表会让翻页也
付一次代价）。没回来之前显示 `—` 而不是「正常」：把「还不知道」显示成「没问题」是最不
该有的谎。拉取失败也只影响这一列。

### 概览页入口（双向）

- 首页异常区会出现「N 张拓扑画布存在异常节点」，点条目直接进那张图。数字与图上的颜色
  同源（后端同一份 issues 判定）。
- 已有的异常明细（证书快过期、域名异常、解析同步失败、Agent 离线…）右侧多出「所在链路
  图」标签（`components/dashboard/DutyBlocks.vue`，生产环境的画布标红）。标签点击带
  `@click.stop`，否则会连带触发条目自己那条跳转。字段不存在时不渲染——没画进任何图的
  异常不该出现一个空壳标签。

### 只读用户

`topo=read` 的账号拿到同一套界面，只是不渲染保存/编排/删除按钮，画布本身
`nodes-draggable`、`nodes-connectable` 关掉（仍可缩放平移查看）。看图的人比画图的人
多得多，不值得为此维护第二个组件。
