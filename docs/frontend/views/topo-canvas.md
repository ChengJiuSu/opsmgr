# 拓扑画布（views/topo/Canvases.vue · CanvasEditor.vue）

**路由：** `/topo/canvases`（列表）· `/topo/canvases/:id`（编辑器，URL 可分享）
**菜单：** 侧边栏「资产管理 → 拓扑画布」，与服务器台账同组
**权限：** `meta.perm = ['topo', 'read']`；写操作按 `authStore.can('topo', 'write')` 显隐
**API：** `src/api/topo.js`（`/api/topo/`，后端模块见 `docs/backend/modules/topo.md`）
**依赖：** `@vue-flow/core`（画布）· `@vue-flow/background` · `@vue-flow/controls` · `dagre`（自动排版）
**通用组件：** `components/ContextMenu.vue`（右键菜单）· `components/TopoImpactDialog.vue`（影响面反查）

---

## 列表页（Canvases.vue）

- 筛选：关键字（名称/标识，300ms 防抖边输边查）+ 项目组 / 渠道 / 环境下拉（字典启用项）。
- 列表：名称（可点开画布）/ 标识 / 维度 tags（生产环境 danger 红标）/ 规模（节点数 + 连线数）/
  说明 / 创建人 / 更新时间。地域留空显示「跨地域」并置灰。
- 新建：名称 + 标识 + 项目组 / 渠道 / 环境 / 地域 + 说明。
- 编辑**只允许改名称与说明**：维度与标识是画布的身份，改了等于换成另一张图，而图上
  节点是按原维度挑出来的，跟着换会得到一张自相矛盾的图。表单里这些字段直接 disabled。
- 删除：二次确认，文案报出会一并删掉的节点/连线数量，并明确**被引用的服务器、域名与
  证书本身不受影响**——这是运维最担心的一件事，不写清楚没人敢点。

## 编辑器（CanvasEditor.vue）

三栏布局，与参考实现同构：

| 区域 | 内容 |
|------|------|
| 顶部 | 返回 / 画布名 + 维度 tags / 未保存标记；右侧：值班开关 · 撤销 · 重做 · 重新加载 · 自动编排 · 重新排版 · 更多（导出/克隆）· 保存 |
| 左侧调色板 | 「平台资源」四类（点击开候选弹窗）+ 外部节点按云厂商分组（点击加入画布） |
| 中间画布 | VueFlow：拖拽移动、四向连接点连线、滚轮缩放、右下角控制条、点网格背景 |
| 右侧详情 | 选中节点/连线的属性编辑与删除；未选中时显示画布概况与失联节点数 |

### 撤销 / 重做

**快照式**，不是命令式：图上就几十个节点，整份深拷贝的代价可以忽略；命令式要为每种
操作写一对 do/undo，删节点还得记住它身上的连线——写十种就有十种写错的机会。

- 栈上限 50 步。栈底是「刚从服务端加载/保存完」的那一份，所以**撤销栈空 = 回到了那个
  状态**，`dirty` 直接跟着栈深走，不用另猜「现在到底改没改」。
- 入栈时机一律在**改动之前**（存的是「改之前长什么样」）。三处特殊：
  - 拖拽在 `node-drag-start` 抓快照，`drag-stop` 比较坐标，**真挪动过才入栈**——
    单击节点也会走一遍 drag-start/stop，不比较的话点一下就多一条历史，还会误标未保存；
  - 右侧面板的文本框在 `focus` 时只**暂存**快照，敲了第一个字才入栈，一次聚焦只记一步
    （否则每敲一个字入一次栈，撤销要按几十下）；
  - `v-model` 已经改掉值的控件（固定位置开关、关系下拉），快照按旧值重建再入栈；
    关系下拉的旧值在 `@focus` 时记下（`el-select` 的 `@change` 只给新值）。
- 删除节点的入栈放在**确认框之后**：取消掉的确认不该留下一条历史。
- 撤销/重做刻意**不重置视口**：人正盯着某一块看，视图跳一下比不跳更难受。恢复时会先收
  掉改名态与右键菜单——节点对象整份换掉，指向旧对象的状态全部作废。
- 保存或重新加载后清栈：服务端刚给的那一份是新基线，撤到那里就到底了。
- 入口三处：工具栏按钮（带禁用态与快捷键提示）、`Ctrl/Cmd+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`、
  空白处右键菜单。输入框内的 `Ctrl+Z` 不拦——那是浏览器的文本撤销，抢过来会让人改不了字。

### 右键菜单与就地改名

高频操作（改名 / 删除 / 改关系 / 固定）原来全在右侧面板：要先点中目标，再把视线和
鼠标挪到屏幕另一边。现在同时挂到右键上，右侧面板保留不动——问题清单、实时附加信息、
备注、副标题只有那儿放得下。

| 触发 | 菜单项 |
|------|--------|
| 节点上右键 | 重命名（引用型置灰并说明「取自平台资源」）· 固定/取消固定 · 打开原始页（引用型）· 查看所在其它画布 · 复制名称 · 断开所有连线（带条数，无连线置灰）· 删除节点 |
| 连线上右键（线上或关系文字上） | 7 种关系直接平铺（当前值打勾）· 删除连线 |
| 空白处右键 | 在此处新建节点（按云厂商二级菜单）· 重新排版 · 适应视图 |

- **就地改名**：双击节点标题或菜单里的「重命名」，原地变输入框，Enter 提交 / Esc 取消 /
  失焦提交。新建外部节点后自动进入改名态——加一个节点后要做的事十有八九是给它起名。
  引用型节点双击标题改为打开原始页：它的名字本来就该在那边改。
- **类型标签也能改**：节点卡片上那行蓝字（「AWS · GA 加速器」）双击即可编辑，引用型节点
  同样可改——它只是给人看的分组名，真实类型始终是 `data.kind`，改它不影响任何判定。
  值存在 `attrs.kind_label`（后端零改动：`attrs` 就是为这类展示细节留的自由字段），
  清空即恢复 `/api/topo/meta/` 给的默认名。右侧面板的「类型标签」一栏与右键菜单的
  「修改 / 恢复默认类型标签」走同一条路；面板那栏用 `@change`（失焦/回车）而不是
  `@input`，否则每敲一个字入一次历史栈。
- **落点**：空白处右键新建的节点落在**光标处**（`screenToFlowCoordinate` 换算画布坐标），
  不再是按节点数错开的固定位置；从左侧调色板加则仍走错开落点。
- **键盘**：Delete / Backspace 删选中的节点或连线；`Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做。自己接而不是交给 vue-flow 的
  `deleteKeyCode`——那条路不走确认框、也不会把改动标成未保存；输入框内的退格照常编辑文字。
- **确认口径**：带连线的节点才二次确认（删掉会静默改变链路形状，那种错不容易发现）；
  孤立节点直接删——删错了 `Ctrl+Z` 撤回。
- **只读 / 值班模式**：菜单只留「看」的动作（打开原始页 / 查看所在画布 / 复制名称），
  键盘删除与撤销重做都不生效。给一堆点了没反应的菜单项比不给更糟。

四个实现上必须处理的点，都在代码注释里写了原因：节点内输入框要 `@mousedown.stop`
（否则一点就开始拖节点）；菜单用 `Teleport` + fixed 定位（挂画布内部会被 transform
缩放）；整图刷新与菜单动作前先收掉改名态（节点对象会被换掉）；值班模式定时刷新在
改名中跳过那一轮（与未保存改动同口径）。

vue-flow 默认只有左键平移（d3-zoom 的 `!event.button` 过滤），所以右键菜单不会和画布
拖动抢事件，不需要关掉 `panOnDrag`。

### 节点 id 用客户端 key，不用数据库主键

新拖出来的节点还没有主键，而连线必须立刻能引用它。所以画布内的 id 一律是客户端
key（已落库的用 `n<主键>`，新建的用 `new-<序号>`），主键另存在 `data.dbId` 里，保存
时回传以更新而非重建。后端整图 PUT 按 key 关联连线（见 `apps/topo_mgr/graph.py`）。

### 调色板分两类

- **平台资源**（服务器 / 主域名 / 解析记录 / 证书）：点击开候选弹窗，从后端
  `candidates` 拉清单（主机按画布维度收窄）。已在图上的资源仍然列出并标「已在图上」，
  不是过滤掉——过滤掉的话用户会以为是搜不到。
- **外部资源**（GA、各家 LB、CDN、WAF…）：点击直接落一个可改名的节点。分组结构来自
  后端 `/api/topo/meta/`，前端不写死一份：加一种负载均衡只改后端登记表，否则漏改的
  表现是「拖得出来但存不进去」。

### 引用型节点的名称不可改

它的名称、副标题、状态由平台实体决定，右侧详情只展示不给编辑（改了保存后仍会被实时
值覆盖，给一个改不动的输入框比不给更糟）。节点卡片左侧色条是健康度，颜色口径与列表页
`el-tag` 一致：绿=正常、黄=警告、红=异常或**已失联**。

失联节点（引用的实体被删）留在图上并弹红色 alert 提示，不静默消失。

### 保存与自动编排

- **保存**：整图一次 PUT，后端事务覆盖。保存后用响应里回传的整图刷新画布——新节点在
  这里第一次拿到主键，引用型节点也拿到实时状态。坐标从 VueFlow store（`getNodes`）读，
  不依赖 v-model 回写的时机。
- **自动编排**：有未保存改动时先拦住（提示先保存），否则新拉的节点会和本地改动混在
  一起，保存时谁覆盖谁说不清。确认框里写明会拉哪些资源、幂等、不动手摆好的节点。
- **重新排版**：dagre `rankdir=LR` 从左到右分层。`data.pinned` 的节点不动——人手摆的
  位置通常带着说不出口的信息（这条链路要横着看），被一次排版抹掉很恼人。
- 有未保存改动时，「重新加载」二次确认、浏览器刷新/关闭走 `beforeunload` 拦截。

### 导出 / 克隆（编辑器「更多」下拉）

- **导出 JSON**：后端吐的是 JSON 对象（引用型节点用自然键），前端落成
  `topo-<slug>.json`。不用 blob 响应类型，是为了让统一响应拦截器照常处理错误——
  blob 模式下后端的中文报错会变成一坨二进制。
- **克隆**：填新名称/标识，维度留空即沿用原画布。换了维度时与新维度不符的主机会被
  后端跳过，前端把跳过清单逐条弹出来（只报个数量，人不知道要补哪些）。克隆后 push
  到新画布——同一个组件实例，所以 `watch(canvasId)` 负责重新拉图，否则标题换了图没换。

### 导入（列表页「导入 JSON」）

选 `.json` 文件（`FileReader` 读成文本，不走 multipart——后端收的是 JSON 体）或直接
粘贴。可覆盖名称/标识/维度；「覆盖已存在」需读写权限，关闭时同维度同标识会直接报冲突。
落地结果同样弹出跳过清单。

### 四向连接点

节点卡片上下左右各一个连接点（`HANDLE_POSITIONS`，id 就是方位词，落库后一眼能读懂）。
只画一个 `Handle`（`type="source"`）+ `connection-mode="loose"`：宽松模式下每个点既能当
起点也能当终点，不必在同一位置叠一个 source 一个 target。

竖着的关系（解析记录 → 证书）如果只能右出左进，线会绕一个大弯从卡片侧面兜过去，图上
看着像连错了——这是加它的唯一理由。

- 连接点平时是个小灰点不抢视线，鼠标进到卡片上再放大变蓝，好瞄。
- 连接点**落库**（`TopoEdge.source_handle/target_handle`）：不存的话保存一次，人手调好
  的走线全弹回左右两侧。没记连接点的老数据（含自动编排生成的边）按「右出左进」画，与加
  这个功能之前的走线一致。
- 去重仍然只看「哪两个节点 + 什么关系」，不看连接点：同一对节点之间同一种关系换个方向
  再连一条，图上就是两条重合的线，后端唯一约束也会拦。

### 连线为什么要自定义组件（views/topo/TopoEdge.vue）

「右键连线改关系」用默认连线做不到，两处都点不上：

1. 可见描边只有 1px，右键得正好压在那条曲线上；
2. 关系文字由 `.vue-flow__edge-labels` 层渲染，那层 CSS 是 `pointer-events: none`，
   而且它在连线的 `<g>` 之外——右键点在文字上既不触发 vue-flow 的 `edgeContextMenu`，
   也传不到连线自己身上。

而人本能会去点那两个字：曲线又细又弯，文字才是这条线唯一像「把手」的东西。

所以连线换成自定义类型（`buildEdge` 里 `type: 'topo'`）：路径走 `BaseEdge` 并给
`interaction-width="30"`（一条 30px 的透明交互描边，线上任意处都好点），标签自己渲染并
打开 `pointer-events`，带 `@contextmenu` 与 `@click`。两条路通到同一个
`openEdgeMenu(event, edgeId)`——菜单函数由画布 `provide` 下来，连线组件不该知道菜单长
什么样。

关系项**直接平铺**不做二级菜单：关系是这个菜单唯一的高频动作，藏进「改关系 ›」要多一次
悬停对准，而鼠标从菜单项往子菜单挪的路上很容易划出去。

右侧面板那个关系下拉保留——选中连线后在那儿改同样有效，右键只是把它变成一步。

### 连线的视觉编码（views/topo/edgeStyles.js）

连线原来全是同色同粗，只靠中间那两个字区分关系：图一密就得挨个凑近读标签，
而运维看这张图问的第一个问题从来是「流量怎么走的」，不是「这条线叫什么」。

- **颜色 + 线型双通道**：七种关系各有颜色，回源/挂载/关联再叠虚线与点线。不只用颜色是
  因为约 8% 的男性有红绿色觉障碍——只靠色相等于对他们没做区分。映射表在
  `edgeStyles.js`，后端 `RELATIONS` 加一种而这里漏配不会崩（回落灰色虚线），
  但线型就区分不出来，所以两处要一起改。
- **箭头按关系着色**：`markerEnd` 给**对象**形式（`{ type, color }`），vue-flow 会按内容
  去重生成 `<marker>` defs，所以最多七个定义，与边数无关。给字符串形式则所有边共用一个
  默认色箭头——那正是「线有颜色、箭头统一灰」的来源。箭头由连线组件按 `data.relation`
  算，不写死在边对象上：关系可以在图上随时改（右键菜单 / 右侧下拉），写死就得在每个改
  关系的地方记着同步一次，漏一处就是「线紫箭头蓝」。
- **走线仍是贝塞尔曲线**：试过正交折线（`getSmoothStepPath`），在这张图上更糟——节点是
  四向出线的自由布局不是分层电路，折线会沿着同一条水平/垂直轴大段重叠，两条线压成一条；
  曲线各自的弧度天然把它们错开。曲率走 `EDGE_CURVATURE`（0.25，vue-flow 默认值），
  写出来只为它可调：曲率再大相邻两条会鼓成两个并排的气泡，反而更难分。
- **末端扇形偏移**：多条线汇聚到同一个连接点时箭头精确重合，只看得见最后画的那条。
  `computeFanOffsets()` 按「目标节点 + 目标连接点」分组，左右进偏 Y、上下进偏 X，
  步长 9px 并封顶 36px（再多就甩出卡片外了——那时候该做的是理图，不是靠画线技巧救）。
  分组内按 source id 排序而不是数组下标：下标会随「谁先被加进来」变，同一张图两次打开
  线的上下顺序不一样，人会以为图改了。
- **图例**贴在画布左下角，只列图上真实出现过的关系（七种全摆出来要人先找哪几个跟自己
  有关），线型同样从配置读，不在 CSS 里另写一份。

### 点击 / 悬停高亮整条链路

「这台机 / 这个域名，上下游是谁」——看拓扑图最高频的一问，原来只能靠眼睛顺着线爬，
线一交叉就爬丢。现在点中或悬停一个节点，**经过它的那整条链路**（域名 → 加速 → 负载均衡
→ 后端机）整段保持原样并流动，其余边压到 0.15 透明度。

只亮一跳等于让人点一下走一格，点到终点还得自己在脑子里把几段拼起来，所以走多跳。
方向上**分两次有向 BFS**：顺出边走「它能流到哪儿」，顺入边走「谁能流到它」，两个集合合并。
不能把边当无向图一次 BFS——无向遍历会顺着任意一条边往回再往外爬，一路漫到整个连通分量，
而这张图上绝大多数节点是连通的，结果是「全亮 = 没亮」。分开走则共用同一个上游的旁支
（兄弟节点）不亮：流量不经过它，它不在这条链路上。

遍历前先按 `edges` 建一份出边/入边邻接索引（`adjacency`，O(E)，只依赖 edges，拖节点不
重算），否则每跳都要扫一遍全部边，链路一长就退化成 O(V×E)。BFS 队列用游标而不是
`shift()`（shift 每次挪整个数组，白送一个 O(n²)），并带 `seen` 防环——「A 回源 B、
B 又落地回 A」这种环在拓扑图上是真实存在的。

两种触发方式，区别不只是「谁点的」，还决定压暗压多狠：

| 来源 | 何时消失 | 无关边 | 无关节点 |
| --- | --- | --- | --- |
| 悬停（transient） | 鼠标移开 | 0.15，不可点 | 0.15，不可点 |
| 点击（sticky） | 点空白 / 换选中 | 0.15，仍可点 | 0.45，仍可点 |

点击态**绝不能**把其余卡片压到点不动：人接着要做的十有八九就是点链路上的下一个节点，
或者换一个节点看，压死等于把人锁在当前选择里，只能先点空白才能继续。悬停态则相反，
鼠标此刻正贴着某个节点划过，关掉无关卡片的点击反而避免误点——反正一挪就恢复。

悬停优先于选中：选中 A 之后把鼠标移到 B 上，人想看的是 B；鼠标移开回到 A。

实现上**不改 `edges` 数组**：改边的 style/class 会触碰 v-model 绑定的数组，vue-flow 要走
一遍边的 diff，还很容易顺手把 `dirty` 标脏（悬停不是改动，标脏了人会以为自己动了图）。
改为在编辑器里算一份 `{ active, sticky, nodes, edges }` 集合 `provide` 下去，连线与节点
自己读：集合算一次是 O(V+E)，连线那边只做 `has`。反过来让每条边自己遍历全图判断
「我在不在链路上」，100 条边就是 100×100。

- 拖拽中（`dragSnapshot` 非空）不高亮：鼠标压着节点走，沿途每个节点都会闪一下，图在抖。
- 压暗时是否关掉 `pointer-events` 按上表分档，别一刀切。
- 边标签也要跟着暗——白底文字不暗下去的话，图上会剩一片浮着的字，比线本身还抢眼。
- 节点只给 `opacity` 加过渡，不给 `transform`：节点同时还在被拖动，给 transform 加过渡会
  让拖拽出现橡皮筋一样的滞后。

### 方向：静态靠箭头，动态留给鼠标指到的那条链路

一开始流动动画是默认全图跑的，理由是「进图第一眼就该看见流量往哪儿走」。实际用下来
满图几十上百条线同时有东西在跑是持续的动态噪声，看图的人反而定不下来看某一处。现在：

- **默认静态**，方向由箭头交代——**端点一个 + 曲线正中一个**。端点那个挨着节点卡片，
  几条线挤在同一个连接点时叠成一小撮，光靠它得把视线顺着曲线爬到头才知道往哪儿流。
- **流动留给「我正在追这一条」的时刻**：鼠标指到某个节点，经过它的那整条链路亮起来并流动，
  其余压暗且一律不动。

中段箭头的做法：`marker-mid` 只认**顶点**，而贝塞尔曲线中间没有顶点，所以把那条三次贝塞尔
用德卡斯特里奥在 t=0.5 处劈成两段（连取中点即可），两段的公共端点就是可以挂箭头的顶点。
分割后的曲线与原曲线**逐点重合**，图形一点不变。方向由浏览器按 `orient="auto"` 自动算切线。

- 控制点是从 `getBezierPath` 吐出的 `d` 字符串里**解析**的，不是照着 vue-flow 的曲率公式
  再算一遍：公式属于它的内部实现，跟着版本变，抄过来迟早对不上；而「一个 M + 一个 C」的
  输出形状是稳定的。解析不出 8 个数就原样返回——没有中段箭头，但线绝不会画错。
- `<marker>` 定义由画布统一渲染一份（每种关系一个颜色），放在画布里一个零尺寸 `<svg>` 中：
  SVG 的 `url(#id)` 是全文档解析的，不必塞进 vue-flow 自己那个 `<svg>`，塞进去反而会被它
  每次重渲染连坐。连线侧用 CSS 属性 `marker-mid` 引用（BaseEdge 的 `inheritAttrs: false` +
  `mergeProps(attrs)` 会把我们的 `style` 落到那条 path 上）。
- `markerUnits="userSpaceOnUse"`：默认的 `strokeWidth` 单位会让箭头跟着线粗变大，高亮时线
  从 1.8 变 3，箭头跟着跳一下，像是图动了。用户空间单位则跟着画布缩放走，与线粗无关。

**流动的三道闸门**（开关打开、或链路被点亮时仍然适用）：

- **边数阈值**：超过 `FLOW_MAX_EDGES`（160）自动降级为「只有选中/高亮的线在动」，不等人
  自己发现卡了再去翻开关。顶部「流动」开关此时一并禁掉并在 tooltip 里说明——开着却不动
  比关着更让人困惑。
- **压暗的边一律停**：高亮时全图只剩一条链路在动，其余当场停下。既省重绘，也是视觉上的——
  0.15 透明度的线还在爬是干扰不是信息。
- **顶部「流动」开关**存 `localStorage`（键 `topo.showFlow`，**默认关**），与「服务」开关同
  口径：它不改变任何人看到的数据，只影响这台机器上图动不动，不进后端。留着它是给「我就想
  看全图在流」的人一个口子。

选中/高亮的线**永远**跑，哪怕全图开关关了或被阈值降级——用户刚指到它，得让它从图里跳
出来。未点亮且全图关闭时那条动画 `<path>` 连 DOM 都不生成（`v-if` 而不是 CSS 关动画）。

走 `stroke-dashoffset` 动画而不是沿路径跑的小圆点（`animateMotion`）：小圆点每条线要多一个
SMIL 节点和一次路径采样，dashoffset 只是一个属性动画，且路径变了不用重新采样。一轮的位移量
必须等于一个完整周期（归一化后就是全长），否则每轮结束会跳一下——所以 `FLOW_PERIOD` 与
`FLOW_DASH` 同出一处，经 CSS 变量 `--flow-period` 传给 `@keyframes`，不在两处各写一个数。

**流动的形式走过四版**，记下来免得再走回去：

| 版本 | 做法 | 问题 |
| --- | --- | --- |
| 一 | `6 8` / 0.9s，亮段与底线同色同宽 | ≈15px/s 比人眼判定「在动」的阈值还慢；同色同宽叠一起只是变粗，没有对比 |
| 二 | `10 16` / 0.65s，底线压淡 | 动是看出来了，但整条线铺满等距亮段，几十条一起爬像毛毛虫 |
| 三 | 单段长光（占全长 14%） | 不密集了，但一截长条滑过去仍像一条虫在蠕动 |
| 四（当前） | **一个圆点沿线走** / 1.6s | — |

点没有长度，也就没有「蠕动」这回事，方向由它往哪儿走交代得一清二楚，是四版里最安静的。

**圆点不是另画一个 `<circle>` 沿路径跑**（`animateMotion` 每条线要多一个 SMIL 节点和一次
路径采样），仍旧是同一个 `stroke-dashoffset` 动画：dash 段长取到近乎为零，配
`stroke-linecap: round`，圆头把这个零长度段渲染成一个圆——直径就是描边宽度
（`EDGE_WIDTH.dot` = 7，相对 base 1.8 够显眼又不盖住两端箭头）。所以 CSS 里那行
`stroke-linecap: round` 是圆点的来源不是装饰，改成 `butt` 会什么都画不出来。

dash 长度取 `0.1` 而不是 `0`：零长度子路径在部分渲染器上会被整段跳过，什么都不画。

长度单位靠给流动路径加 `pathLength="100"` 归一化，dasharray 从此按**全长的百分比**算，
与这条线实际多长无关——不然短边长边得各配一套 dash。代价是每条线跑完一趟耗时相同、
**线越长点走得越快**；换成按像素定速可以让全图点速一致，但那样短边上的点一闪就没、长边上
半天爬不到头，反而更难跟。（属性名是驼峰 `pathLength`，SVG 属性区分大小写，写成
`path-length` 浏览器不认。）

底线在跑流动时退成轨道：`stroke-opacity` 压到 0.5（`EDGE_OPACITY.track`），圆点跑在上面
才有对比。压的是 **`stroke-opacity` 而不是 `opacity`**——后者是元素级的，会把箭头一起压淡，
变成线亮箭头淡；`stroke-opacity` 只作用于描边，marker 自带 fill 不受影响。（dim 那一档仍用
`opacity`，那里正需要箭头跟着一起暗。）不压得更淡，是因为一条线上大半时间没有点，太淡就
看不清它连去哪儿。

`prefers-reduced-motion` 的处理从 CSS 挪到了 JS（`edgeStyles.js` 导出一个 `matchMedia`
驱动的 ref）：只在 CSS 里关掉 animation 会留下「淡轨道 + 一截静止亮段」，比动着还难读；
现在直接不渲染那条路径，底线保持原样，高亮就是纯粹的加粗加亮。

### 影响面反查（components/TopoImpactDialog.vue）

通用弹窗，服务器页与域名页的行操作各挂一个「拓扑」按钮（按 `authStore.can('topo')`
显隐——没有画布权限的人看到一个点开就 403 的按钮只会困惑）。

弹窗左右两栏：上游（谁的流量落到它身上）/ 下游（它指向谁），每条带关系标签与邻居
节点名，节点名按健康度着色（口径与画布节点一致）。点画布名跳进那张图。

做成组件而不是各页面各写一份：两个页面问的是同一个问题，两份实现迟早在「上游/下游谁
是谁」上说反。

### 值班模式（P3）

顶部开关，状态同步到 URL（`?watch=1`）——大屏那份链接可以直接分享，刷新浏览器也还在
值班模式。开着时：

- **只读**：`editable = canWrite && !watchMode`，连有写权限的人也锁住——一张定时自动
  刷新的图上做编辑，下一次刷新就把改动冲了；
- 每 30 秒重拉整图（有未保存改动时跳过这一轮，绝不冲掉正在画的东西）；30 秒是「大屏
  挂着看」的量级，主机状态与证书天数都不是秒级变化的东西；
- 顶部横幅按最坏级别着色，给出「N 个节点异常 / 全部正常」+ 最近刷新时刻 + 立即刷新；
  横幅数字直接由画布上的节点算（`issueSummary`），不额外拉健康度接口；
- 异常节点呼吸高亮（`.pulse`）：大屏离得远，只靠 4px 色条看不见。

从编辑态切进值班模式时若有未保存改动，先二次确认再丢弃。

### 主机节点上的服务标签

主机卡片下方一行标签，注明这台机负责跑哪些服务（数据见
`docs/backend/modules/topo.md` 的「服务标签」一节）：

- 标签文字是**进程名 ×进程数**（`nginx-01×4`），与「服务器分配」页的「服务进程
  （规划/部署）」列同口径。进程名才是这台机上实际跑的那个东西的标识（同云厂商+项目组+
  环境+渠道内按服务类型自动递增编号），排查时要 grep 的就是它；服务类型名（「战斗服」）
  是分类，同一类在不同机器上重名，写在卡片上等于没说这台机跑的是哪一个。没规划过进程名
  的旧记录回落到类型名。类型名放 hover 与右侧面板——卡片要短，但「nginx-01 是干什么的」
  也得能问出来。
- `deployed` 实心绿、`planned` 虚线黄——一眼分清「在跑」和「还没上」。
- 卡片最多铺 **3 个**，多的收成 `+n`，hover 显示全部（带状态与进程名）。一台机六个
  服务全铺开，卡片会比别的节点高一倍，整张图的行距就乱了。
- 顶部「服务」开关控制显隐，存 `localStorage`（键 `topo.showServices`，默认开）——
  与概览页区块显隐同口径，按人记不进后端：它不影响任何人看到的数据，只影响这台
  浏览器上卡片有多高。读写都包了 try，隐私模式下取不到就用默认值。
- **dagre 布点高度跟着它走**（`nodeHeight()`）：卡片高了还按固定 78 布点，「重新排版」
  一按就叠在一起。
- 右侧面板另有「服务进程」一栏：进程名 tag + 进程数 + 服务类型名 + 状态。通用的
  `extra` 键值行显示不了这些，所以 `services` 从那份通用渲染里摘出来单列。

### 节点问题清单

右侧详情的「问题」一栏列出后端给的 `issues`（黄/红分色）：主机维护中、执行通道 Agent
离线、解析记录已停用、证书还剩几天……只给颜色不给原因，人还得自己去翻三个页面。

### 列表页的「健康」列

列表拉完后再补一发 `/api/topo/health/`（汇总要遍历所有引用型节点，绑进列表会让翻页也
付一次代价）。没回来之前显示 `—` 而不是「正常」：把「还不知道」显示成「没问题」是最不
该有的谎。拉取失败也只影响这一列。

### 概览页入口（双向）

- 首页异常区会出现「N 张拓扑画布存在异常节点」，点条目直接进那张图。数字与图上的颜色
  同源（后端同一份 issues 判定）。
- 已有的异常明细（证书快过期、域名异常、解析同步失败、Agent 离线…）右侧多出「所在链路
  图」标签（`components/dashboard/DutyBlocks.vue`，生产环境的画布标红）。标签点击带
  `@click.stop`，否则会连带触发条目自己那条跳转。字段不存在时不渲染——没画进任何图的
  异常不该出现一个空壳标签。

### 只读用户

`topo=read` 的账号拿到同一套界面，只是不渲染保存/编排/删除按钮，画布本身
`nodes-draggable`、`nodes-connectable` 关掉（仍可缩放平移查看）。看图的人比画图的人
多得多，不值得为此维护第二个组件。
