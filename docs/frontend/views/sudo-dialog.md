# 二次验证弹框（SudoDialog.vue）

**文件：** `src/components/SudoDialog.vue`（全局挂在 `App.vue`）
**协调器：** `src/utils/sudo.js`
**后端：** [auth_mgr](../../backend/modules/auth.md#敏感操作二次验证sudo)、
[飞书接入](../../backend/modules/im_mgr.md#sudo-卡片确认)

---

## 触发方式

页面**不需要任何处理**。配置面的写操作后端返回 403 + `error_code=sudo_required`，
`utils/request.js` 的响应拦截器弹出本框，验过之后**重放原请求**——加一个受控接口
不需要改任何前端代码。

拦截器同时把「这次要做什么」按请求路径翻成人话（`describeAction`）传进来，
飞书确认卡上要写它。

---

## 三条验证路径

| 路径 | 什么时候出现 |
|------|-------------|
| 验证器动态码 | 用户已绑定 MFA（后端 `GET /api/auth/mfa/sudo/` 的权威口径） |
| 登录密码 | 未绑定 MFA |
| **飞书卡片确认** | `GET /api/feishu/sudo/` 回 `available`（未绑定飞书、已绑验证器且配置为「仅未绑验证器」、功能关闭，三种情况都不出现） |

前两条互斥（按是否绑定 MFA 切换），飞书那条是**附加**的支路，出现在框底部。

**是否显示由后端判**，不用本地缓存的 user：用户可能刚在别处绑了 MFA，本地那份是旧的。

---

## 飞书确认的交互

```
点「用飞书确认」
  → POST /api/feishu/sudo/ 推卡片到本人私聊，返回 token 与有效期
  → 每 2 秒 GET /api/feishu/sudo/?token=…
  → 拿到 state=granted：窗口已开 → settleSudo(true) → 拦截器重放原请求
```

**轮询而不是等推送**：这条链路上没有 WebSocket，而 2 秒一次、最多两分钟的开销，
远小于为它单拉一条长连接。

倒计时归零、票据失效、换了登录会话，都会停掉轮询并给出提示。取消弹框与组件卸载时
同样清掉定时器——否则用户关掉框之后还在后台打接口。

---

## 两处防重复提交

- **验证码填满自动提交**后用户再回车/点按钮，第二次拿同一个码去校验必然撞后端防重放，
  报「已使用过」却其实已经放行——最费解的一种错。用 `lastSubmitted` 挡住。
- **飞书确认等待期间禁用表单提交按钮**，避免两条路同时走。
