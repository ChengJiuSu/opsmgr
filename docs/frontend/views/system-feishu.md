# 飞书接入（Feishu.vue）

**路由：** `/system/feishu`（`perm: ['system', 'write']`）
**文件：** `src/views/system/Feishu.vue`
**后端：** [飞书接入模块](../../backend/modules/im_mgr.md)

---

## 功能

一页管完飞书接入的全部配置面：

- **飞书应用**：App ID 与三把密钥、回调地址展示与轮换、来源 IP 白名单、三个开关
- **会话白名单**：允许与平台交互的群 / 单聊，分页 CRUD

菜单位置：系统管理 → 飞书接入（`system` 模块 write 档可见）。

---

## 页面结构

```
飞书接入
├── el-alert（missing_fields 非空时）——「启用前还需配置：…」
├── el-card 飞书应用
│   ├── App ID / App Secret / Encrypt Key / Verification Token
│   ├── 分隔线「回调入口」：事件订阅地址、卡片回调地址（只读 + 复制）+ 轮换按钮
│   ├── 分隔线「来源限制」：不限制来源 IP 开关 + IP 白名单文本域
│   └── 分隔线「开关」：启用接入 / 启用飞书登录 / 登录回调地址 / 自动建号 / 备注
└── el-card 会话白名单
    ├── toolbar：关键字搜索 + 新增会话
    ├── el-table：名称 / 会话 ID / 类型 / 允许执行 / 通知 / 状态 / 备注
    └── el-pagination
```

## 几处刻意的交互

**密钥留空 = 不修改。** 三个密码框的 placeholder 按后端回的 `has_xxx` 切换成
「已配置，留空表示不修改」，加载与保存后一律清空表单里的密钥值。否则每次改个 IP
白名单都要把三把密钥重新粘一遍，粘错了还查不出来。

**轮换回调地址要二次确认。** 轮换后旧地址立即失效，不到飞书后台同步更新就会
**所有回调全部被拒**，确认文案把这个后果写明。

**自动建号开关要二次确认。** 打开等于任何飞书成员登录即获得平台账号，
确认框写清楚「只读、无执行能力、无可用密码」；取消则把开关拨回去。

**「启用飞书登录」在未启用接入时禁用。** 与后端校验同一口径，避免提交后才报错。

**IP 白名单提示两层都要放行**：这一份是应用层的（存库），nginx 侧还有一份
`deploy/nginx/conf/snippets/feishu_callback_ips.conf`。

**「允许单聊发起执行」** 单独一个开关：机器人自定义菜单是在单聊里点的，而菜单事件的
payload 里**没有 chat_id**，没法登记到会话白名单，只能用总开关表达同一个授权意思。
群里仍按白名单，两者互不影响。

**「sudo 卡片确认」** 三档（关闭 / 仅未绑验证器 / 所有人），默认只兜底——卡片点一下
比翻验证器摩擦小，容易养成随手确认的习惯。

**会话白名单里的播报订阅**：每条会话可单独配「播报范围」（默认仅失败）与两个维度
过滤（项目组 / 环境，空 = 不限）。会话 ID 收群 `oc_…`，也收个人 `ou_…`（open_id）
——只用单聊的人同样要能收播报。

**复制按钮失败有兜底**：http 页面或浏览器拒绝时拿不到剪贴板 API，提示用户手动选中。

## sudo

本页所有写操作后端都挂了 `SudoRequired`，前端**不需要任何处理**——
`utils/request.js` 的响应拦截器识别 `error_code=sudo_required` 后弹验证框并重放
原请求（见 `utils/sudo.js`）。
